#+title: mysql

[[https://melpa.org/#/mysql][file:https://melpa.org/packages/mysql-badge.svg]]

A pure Emacs Lisp MySQL wire-protocol client. It talks to the server directly instead of shelling out to the =mysql= CLI.

* Requirements and installation

Requires Emacs 28.1 or newer, with no external CLI or third-party Lisp dependencies. Tested against MySQL 5.6+, MySQL 8.x, and MariaDB 10.11.

Install =mysql= from MELPA:

#+begin_src emacs-lisp
(package-install 'mysql)
#+end_src

* Basic usage

#+begin_src emacs-lisp
(require 'mysql)

(let ((conn (mysql-connect :host "127.0.0.1"
                           :port 3306
                           :user "root"
                           :password "secret"
                           :database "mydb")))
  (unwind-protect
      (let ((result (mysql-query conn "SELECT 1 AS n")))
        (message "Rows: %S" (mysql-result-rows result)))
    (mysql-disconnect conn)))
#+end_src

You can also connect with a percent-decoded =mysql://= URI via =mysql-connect-uri=, or scope a connection with =with-mysql-connection=.

** TLS and authentication

Supports =mysql_native_password= and =caching_sha2_password= (other server plugins such as =sha256_password= signal an error). Pass =:tls t= to require TLS via Emacs GnuTLS, or =:ssl-mode 'disabled= (alias =off=) to stay on plaintext and skip automatic MySQL 8 TLS retries. TLS verification is on by default and configured via =mysql-tls-verify-server=, =mysql-tls-trustfiles=, and =mysql-tls-keylist=.

** Prepared statements and cursors

Use =mysql-prepare=, =mysql-execute=, and =mysql-stmt-close= for prepared statements, or =mysql-execute-cursor=, =mysql-fetch=, and =mysql-cursor-close= for server-side cursors.

Prepared integer parameters support the full signed and unsigned 64-bit range; values outside that range signal =mysql-stmt-error= before anything is sent.

** Transactions and session state

#+begin_src emacs-lisp
(mysql-set-autocommit conn nil)
(unwind-protect
    (progn
      (mysql-query conn "INSERT INTO demo(name) VALUES ('alice')")
      (mysql-commit conn))
  (mysql-set-autocommit conn t))
#+end_src

=mysql-autocommit-p= and =mysql-in-transaction-p= track server status flags from completed text queries, prepared queries, and OK responses, so a result-set query that opens a transaction in manual mode is reflected immediately without an extra round trip. Other helpers include =with-mysql-transaction=, =mysql-rollback=, =mysql-ping=, =mysql-live-p=, =mysql-busy-p=, =mysql-connection-id=, =mysql-current-database=, =mysql-select-database=, =mysql-refresh-current-database= (which updates the recorded database after a raw =USE= query), =mysql-escape-identifier=, and =mysql-escape-literal=.

* Asynchronous and streaming queries

=mysql-query-async= sends a text query without blocking and calls its callback once from a timer with =(result error)= (where =result= is a =mysql-result= or =nil=). While a query is in flight, =mysql-async-pending-p= returns non-nil and the connection rejects other commands. After a =mysql-query-error= the connection stays usable; any other error closes it. The read-idle timeout does not apply to async queries; stop a slow query by running =KILL QUERY= with its =mysql-connection-id= on another connection, and the callback will receive the server's error.

#+begin_src emacs-lisp
(mysql-query-async conn "SELECT COUNT(*) FROM orders"
                   (lambda (result error)
                     (if error
                         (message "Query failed: %s" (error-message-string error))
                       (message "Rows: %S" (mysql-result-rows result)))))
#+end_src

For large results, use =mysql-query-rows-async= to stream ordered row batches and column definitions to a consumer outside the process filter. If the consumer returns =stop= or signals an error, it stops receiving rows while the remaining response drains (use =KILL QUERY= on another connection to interrupt the server). A successful final callback receives the column definitions without accumulating rows in memory.

* Timeouts and interrupted connections

If a synchronous query times out before its first response packet finishes arriving, the connection refuses new commands until =mysql-drain-query-response= consumes the pending reply. If it times out after result parsing has already started, the connection is closed instead because the stream position can no longer be safely recovered. Quitting or aborting during authentication closes the partial connection and cleans up its process buffer.
